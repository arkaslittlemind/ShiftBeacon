# Changelog

All notable changes to ShiftBeacon are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## How versions are chosen

ShiftBeacon is an application, not a library, so its public contract is what
users, operators, and API clients depend on:

- **Major** - a breaking change to that contract: a REST API route or response
  shape changes incompatibly, a required environment variable is added or
  renamed, a migration needs manual steps, or a role loses access it had.
- **Minor** - a new user-facing capability, a new optional integration, or a
  visible redesign that keeps every existing flow working.
- **Patch** - bug fixes, security hardening that does not change the contract,
  performance work, and documentation.

Each release is tagged `vX.Y.Z` on `master`, and its GitHub release notes are
the matching section below. Versions before 1.0.0 cover the build-up to the
first production deployment.

## [1.6.0] - 2026-09-19

### Added

- **Ask about attendance.** Managers can type a question, or pick a suggested
  starter question, about their own organization's attendance ("Who worked the
  most hours this week?") and get a plain-text answer from a dashboard card.
  Answers are computed by Gemini calling four read-only tools over the existing
  analytics services, in a loop capped at four model rounds, over the last 7
  days of shift records.
- The organization is always taken from the signed-in session; no tool accepts
  an organization or user argument, so a question cannot reach another tenant's
  data.
- Staff are shown to the model only as aliases ("Staff 1", "Staff 2"); names in
  the question are swapped out before the request leaves the app and swapped
  back in the answer the manager sees.
- Per-manager rate limit of 10 questions per hour, counted atomically in
  PostgreSQL, and a 15-minute answer cache per organization that stores a hash
  of the normalized question, never the question itself. Cached answers cost no
  vendor quota and show when they were produced.
- `POST /api/manager/ask` (manager role only).
- Database tables `AskAnswer` and `AskUsage`, with a migration.
- Attendance eval suite (`evals/attendance.eval.ts`, run with
  `npm run test:evals`): golden questions plus prompt-injection cases,
  including instructions hidden inside a shift note and a cross-organization
  request, asserting that organization scoping holds and only aliases reach the
  model.

### Changed

- README documents the AI features, what is sent to Gemini, and the scrubber's
  known limits.

## [1.5.1] - 2026-09-19

### Fixed

- Two clock-in requests racing from the same worker (a double tap on a slow
  network, or two devices) now return `409` "already active" for the second
  request instead of a generic `500`.
- Two concurrent clock-outs can no longer both succeed; the second now fails
  as "no active shift" instead of overwriting the first clock-out's time and
  location.
- Concurrent dashboard loads for the same organization and day now share one
  handover-digest generation instead of each spending free-tier vendor quota.
- The note scrubber no longer blanks out ordinary words (such as "worker" or
  "night") when a staff member's name happens to contain them.
- A new user is always assigned to the oldest organization, instead of an
  arbitrary one if more than one exists.

### Security

- Clock-in and clock-out notes are limited to 1,000 characters. Previously a
  note had no maximum length and was scrubbed and sent to the AI vendor in full.
- Workplace updates are scoped to the signed-in manager's organization inside
  the service layer, so an organization id can no longer be passed in from
  anywhere other than the session.

## [1.5.0] - 2026-09-19

### Added

- **AI shift handover digest.** The manager dashboard shows a summary of the
  most recent day's clock-in and clock-out notes, with key points and flagged
  items, generated by Gemini with schema-validated output.
- Notes are scrubbed server-side before they leave the app: staff names from
  the organization's roster, email addresses, and phone numbers are redacted
  in one shared place (`lib/ai/scrub-notes.ts`).
- Digests are cached per organization per day in a new `HandoverDigest` table,
  so repeat dashboard views do not spend vendor quota.
- `GEMINI_API_KEY` (optional, server-side only). Without it, or when the vendor
  is unavailable, the card reads as unavailable and nothing else changes.
- Hand-written seed notes so the digest has realistic input.
- Digest eval suite (`evals/handover.eval.ts`): 25 golden cases scored for
  schema validity and key-fact recall, kept out of `npm test` because it calls
  the real API.

## [1.4.0] - 2026-09-18

### Changed

- Interaction polish across the app: press feedback on buttons, smoother hover
  transitions, a crossfade between routes, and a layout height fix.
- Success and error messages in workplace settings, the clock-in panel, and the
  active-shift panel now transition in rather than appearing abruptly.
- Tighter heading tracking on the landing page call-to-action, section heads,
  and page headers.

## [1.3.0] - 2026-09-12

### Added

- The ShiftBeacon logo system: a shield, location pin, and medical cross mark
  with a Space Grotesk wordmark, in the site header and footer, hero, worker
  navigation, and manager sidebar.
- A complete app icon set (512 px down to 16 px, plus a maskable icon), a new
  favicon, and an Open Graph image so shared links show a preview.

## [1.2.0] - 2026-09-12

### Added

- Error monitoring with Sentry, covering server, API route, and client errors,
  with source maps and release tagging. Events are scrubbed of coordinates,
  distances, shift notes, names, and email addresses before sending.
- Product analytics with PostHog. Clock-in succeeded, clock-in rejected (with
  the reason, never the location), clock-out succeeded, and workplace updated
  are recorded server-side after the response, so a slow or unreachable vendor
  cannot delay or break a clock-in. Manager view events are recorded in the
  browser. Autocapture and session replay are off.
- Optional environment variables `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_ORG`,
  `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN`, `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`,
  and `NEXT_PUBLIC_POSTHOG_HOST`. Leaving them out disables the integration
  rather than failing the boot.

## [1.1.1] - 2026-09-12

### Changed

- Each request now looks up the session and the current user once instead of
  several times, which removes redundant database queries on every page.
- README rewritten with screenshots and architecture diagrams.

## [1.1.0] - 2026-09-11

### Added

- Installable app (PWA): web app manifest, app icons, and a service worker that
  caches only the static app shell, never API responses or signed-in pages.
- An offline page shown when there is no connection. Clocking in still needs a
  live connection, since both location and the server check require one.

## [1.0.0] - 2026-09-11

First production release.

### Added

- Startup and build-time validation of required environment variables, with a
  clear error naming any that are missing.
- A shared API error handler that logs server-side and returns consistent error
  responses.
- Database migrations run automatically on deploy (`prisma migrate deploy` in
  `vercel-build` and `start`).

### Fixed

- Production builds on Vercel (a dependency conflict and missing Prisma
  generate and migrate hooks).
- The manager sidebar now shows the real organization name instead of a
  hardcoded placeholder.

## [0.4.0] - 2026-09-09

### Added

- Manager view of staff currently on shift, and each staff member's shift
  history and notes, scoped to the manager's organization.
- Manager analytics: average hours per day, daily clock-ins, and hours per
  staff member over the last 7 days.
- Test suites: unit tests for the geofence math, durations, analytics, and
  validation; API tests for authorization, clock-in and clock-out rules, and
  organization isolation; component tests for worker and manager states; and
  Playwright end-to-end tests for the main worker and manager journeys.

### Changed

- Accessibility: visible keyboard focus, live regions for status messages,
  described charts, labelled form errors, and reduced-motion support.
- Larger touch targets and tighter responsive layouts on phones.
- A consistency pass over typography, borders, shadows, and components.

## [0.3.0] - 2026-09-04

### Added

- Managers can set the workplace name, coordinates, and clock-in radius.
- Care workers can clock in from inside the workplace perimeter, with an
  optional note. The browser's location is checked again on the server; a
  clock-in from outside the radius is rejected, and so is a second active shift.
- Care workers can clock out with an optional note, see the current shift's
  duration, and view their own shift history.

## [0.2.0] - 2026-08-31

### Added

- Sign-in with Auth0 (username and password, Google, or email), with
  `CARE_WORKER` and `MANAGER` roles enforced on the server.
- PostgreSQL schema for users, organizations, and shifts, with a database
  constraint allowing only one active shift per worker, and seed data.
- REST API: current user, organization, shifts, manager staff, and manager
  analytics, with Zod validation and consistent status codes.

## [0.1.0] - 2026-08-27

### Added

- Project foundation: Next.js App Router, TypeScript, Tailwind CSS, and the
  first design system.
- Public landing page and the role-aware application shell for care workers
  and managers, with shared loading, error, and empty states.
